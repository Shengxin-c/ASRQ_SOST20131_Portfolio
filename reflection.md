# Reflection: why reproducibility matters in social research

Reproducibility means that another researcher, given the same data and code, can
obtain the same result. In social research this matters for a reason specific to
the field: our analyses are full of small, consequential choices. How we code a
variable, which model we select, how we handle missing data — each decision can
change the answer. When those decisions are invisible, readers cannot tell
whether a finding reflects the data or the analyst.

The field has paid a price for this opacity. High-profile failures to reproduce
published results have undermined confidence in social science. Transparency —
sharing data, code, and the reasoning behind each choice — is the remedy. It
turns a claim from something we are asked to believe into something we can
verify.

Version control supports this directly. A tool like Git records every change, so
the history of an analysis becomes part of the analysis itself: nothing is
overwritten, and every step can be audited.

For me, reproducibility is also practical. Building an e-portfolio forces me to
write code that others can run, which makes my own work easier to revisit and
reuse. Reproducibility is not an add-on to good analysis; it is what makes
analysis trustworthy.
